# 本番へデプロイする

**このスキルは既にマージされた `main` の内容を本番に反映するためのもの。**
未マージの変更を勝手にデプロイしない。取り返しがつきにくい操作なので、実行前に必ず
ユーザーに何をデプロイするか（対象コミット）を確認する。

デプロイ手順はプロジェクトごとに違うので、**`AGENTS.md` の「デプロイ」節に従う。**
手順が書かれていない、または「未定」となっているなら、**ここで止めてユーザーに手順を確認する。**
推測でデプロイ先に書き込まない。

## 1. 対象を確認する

```powershell
git status --short --branch
git log --oneline -5
```

既定ブランチ（通常 `main`）の最新であることを確認する。作業ブランチのままデプロイしようとしていないか確認する。

## 2. 検証を実行する

```powershell
.\.claude\scripts\run-checks.ps1
```

**1 つでも失敗しているなら、デプロイを止めて報告する。** ユーザーが明示的に
「検証が落ちていてもデプロイして」と言わない限り進めない。

## 3. ビルドとデプロイ

`AGENTS.md` の「デプロイ」節の手順を順に実行する。

- 本番のデータ（保存データ、DB のスキーマなど）に影響する手順は、実行前に内容をユーザーと確認する
- 利用枠・課金に影響する操作は事前に警告する

## 4. 動作を確認する

デプロイして終わりにしない。`AGENTS.md` に書かれた確認項目を確かめる。
実機確認が必要なものはユーザーに依頼する。

## 5. 報告する

- デプロイしたコミット
- 実行した手順
- 確認した内容
- 問題があれば切り戻し手順

## 守ること

- 検証が通っていない状態でデプロイしない
- 本番データに影響する操作は事前にユーザーと内容を確認する
